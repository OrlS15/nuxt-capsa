---
title: Multiple Databases
description: Declare several databases under capsa.db, pick one in server code, and set each one's connection.
---

Every key under `capsa.db` is a database with its own dialect, driver and migrations. The `default` key is required, and any other name adds one more database.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'postgresql', driver: 'pglite', migrations: 'onStart' },
      analytics: { provider: 'drizzle', dialect: 'sqlite', driver: 'node-sqlite', migrations: 'manual' },
    },
  },
})
```

[Setup](/database/drizzle/setup) lists the options of each entry.

## Pick a database

`useCapsaDb()` without an argument returns the `default` database. Pass a name to get another one.

```ts twoslash [server/api/stats.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { events } from '#capsa/db/analytics/schema'

export default defineEventHandler(async () => {
  const users = await useCapsaDb().query.users.findMany()
  const views = await useCapsaDb('analytics').select().from(events)
  //    ^?
  return { users, views }
})
```

A name that isn't configured:

```ts twoslash [server/api/stats.get.ts]
// @errors: 2345
const db = useCapsaDb('logs')
```

## Import a database

Each database also has its own module, `#capsa/db/<name>`. Its `getDb()` returns the same instance as `useCapsaDb('<name>')`.

```ts twoslash [server/utils/track.ts]
import { getDb } from '#capsa/db/analytics'
import { events } from '#capsa/db/analytics/schema'

export function track(name: string, userId?: number) {
  return getDb().insert(events).values({ name, userId, at: new Date() })
}
```

## One folder per database

A database reads its schema, relations, config and migrations from `server/capsa/db/<name>/`.

```bash [Project]
server/capsa/db/
├── default/
│   ├── schema/
│   │   ├── users.ts
│   │   ├── posts.ts
│   │   └── comments.ts
│   ├── relations.ts
│   ├── config.ts
│   └── migrations/
└── analytics/
    ├── schema.ts
    └── migrations/
```

Run drizzle-kit on one database at a time, with the config Capsa generates for it.

```bash [Terminal]
npx drizzle-kit generate --config .nuxt/capsa/db/analytics/drizzle.config.ts
```

[Schema](/database/drizzle/schema), [Relations](/database/drizzle/relations), [Config file](/database/drizzle/config-file) and [Migrations](/database/drizzle/migrations) explain what goes in each file.

## Connection variables

Each database reads its connection from its own environment variable: `NUXT_CAPSA_DB_`, then the name in upper snake case, then `_CONNECTION`.

| Database | Variable |
|---|---|
| `default` | `NUXT_CAPSA_DB_DEFAULT_CONNECTION` |
| `analytics` | `NUXT_CAPSA_DB_ANALYTICS_CONNECTION` |
| `analyticsDb` | `NUXT_CAPSA_DB_ANALYTICS_DB_CONNECTION` |
| `logs_2` | `NUXT_CAPSA_DB_LOGS_2_CONNECTION` |

When the variable is not set, an embedded driver uses a local store named after the database, such as `.data/capsa/db/default` and `.data/capsa/db/analytics.db`. Everything else about connections is in [Connection](/database/drizzle/connection).

## Names

A name may use the letters `a-z` and `A-Z`, digits and `_`. Anything else stops the build:

```text [Terminal]
ERROR  [capsa] invalid db source name "my-db": use only letters, numbers and "_".
```

## Unused databases

A database costs nothing until it opens its connection ([Opening and closing](/database/drizzle/connection#opening-and-closing)). A missing connection fails only the requests that use that database, unless its migrations run `'onStart'`, which [stops the server](/database/drizzle/migrations#apply-on-start).
