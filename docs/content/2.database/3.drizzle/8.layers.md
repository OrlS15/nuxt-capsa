---
title: Layers
description: How a Nuxt layer adds tables and relations to a database, and which files stay with the project.
---

A [Nuxt layer](https://nuxt.com/docs/4.x/getting-started/layers) can add schema files and a `relations.ts` to any database of the project. It uses the same folder path as the project, and Capsa merges the files of both into one database.

```bash [Project]
server/capsa/db/default/
├── config.ts
├── relations.ts
├── migrations/
└── schema/
    ├── comments.ts
    ├── posts.ts
    └── users.ts
layers/shop/
├── nuxt.config.ts
└── server/capsa/db/default/
    ├── relations.ts
    └── schema/
        ├── orders.ts
        └── products.ts
```

The folder follows the database's `dir` option in every layer too ([Schema](/database/drizzle/schema)).

## One database

A layer's tables join the project's: `useCapsaDb()` queries them, and `#capsa/db/default/schema` exports them next to the project's tables.

```ts twoslash [server/api/products.get.ts]
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(async () => {
  const products = await useCapsaDb().query.products.findMany()
  //    ^?
  return products
})
```

## Relations in a layer

A layer declares the relations of its tables in its own `relations.ts`, with `defineRelationsPart` like the project's ([Relations](/database/drizzle/relations)).

```ts twoslash [layers/shop/server/capsa/db/default/relations.ts]
import { defineRelationsPart } from 'drizzle-orm'
import * as schema from '#capsa/db/default/schema'

export default defineRelationsPart(schema, r => ({
  products: {
    orders: r.many.orders(),
  },
  orders: {
    product: r.one.products({ from: r.orders.productId, to: r.products.id }),
  },
}))
```

Use `defineRelationsPart` in every relations file, the project's too. `defineRelations` returns an entry for every table, so it wipes out the relations of the files read before it.

## Which relations win

Capsa reads the relations files in [layer priority](https://nuxt.com/docs/4.x/getting-started/layers#layer-priority) order, lowest first, and the project's last. When two files have an entry for the same table, the later entry replaces the earlier one as a whole, so the project repeats the relations it keeps.

```ts twoslash [server/capsa/db/default/relations.ts]
import { defineRelationsPart } from 'drizzle-orm'
import * as schema from '#capsa/db/default/schema'

export default defineRelationsPart(schema, r => ({
  // users, posts, comments…
  products: {
    // Repeated from layers/shop, whose `products` entry this one replaces.
    orders: r.many.orders({ from: r.products.id, to: r.orders.productId }),
    bulkOrders: r.many.orders({
      from: r.products.id,
      to: r.orders.productId,
      where: { quantity: { gte: 10 } },
    }),
  },
}))
```

::tip
A `many` without `from` and `to` looks for its matching `one` only in the same file. When that `one` is in another file, as `orders.product` is here, write `from` and `to`, or the server stops at start.
::

## Project-only files

`config.ts` and `migrations/` come from the project only. A layer's migrations never ship with the server, and a layer's `config.ts` is ignored with a warning:

```text [Terminal]
[capsa]  WARN  /path/to/app/layers/shop/server/capsa/db/default/config.ts is ignored: a db source takes its config from the project, not from a layer.
```

## Migrations for layer tables

`drizzle-kit generate` reads the schema files of the project and of every layer. It writes the migration into the project's `migrations/` folder, next to the others ([Migrations](/database/drizzle/migrations)).

```bash [Terminal]
npx drizzle-kit generate --config .nuxt/capsa/db/default/drizzle.config.ts
```

## Export names

Every export of a database's schema files needs a name of its own, across the project and its layers. When two files export the same name, the server build stops and names both files:

```text [Terminal]
[capsa] db source "default": `posts` is exported by more than one schema file (`/path/to/app/server/capsa/db/default/schema/posts.ts`, `/path/to/app/layers/blog/server/capsa/db/default/schema/posts.ts`). Rename all but one.
```

## Layers outside the project

A layer can sit outside the project folder, such as a monorepo package added with `extends`.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['../packages/shop'],
})
```

drizzle-kit and the editor load the layer's schema files from that folder, so `drizzle-orm` must resolve from there, as a dependency of the layer or of a workspace root above it.
