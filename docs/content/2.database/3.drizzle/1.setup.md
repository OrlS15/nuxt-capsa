title: Setup
description: Install Drizzle and declare a database under capsa.db in nuxt.config.ts.
---

Each key of `capsa.db` is a database that Capsa builds with Drizzle, using the packages you install in your project.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-capsa'],
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'postgresql', driver: 'pglite', migrations: 'onStart' },
    },
  },
})
```

## Install the packages

Add `drizzle-orm` and your driver's package as dependencies, and `drizzle-kit` as a dev dependency. Capsa needs Drizzle v1 (1.0.0-rc.5 or later), which the `rc` tag installs.

::code-group
```bash [pnpm]
pnpm add drizzle-orm@rc @electric-sql/pglite
pnpm add -D drizzle-kit@rc
```

```bash [npm]
npm install drizzle-orm@rc @electric-sql/pglite
npm install -D drizzle-kit@rc
```

```bash [yarn]
yarn add drizzle-orm@rc @electric-sql/pglite
yarn add -D drizzle-kit@rc
```

```bash [bun]
bun add drizzle-orm@rc @electric-sql/pglite
bun add -d drizzle-kit@rc
```
::

`@electric-sql/pglite` is the package for the `pglite` driver, and [Drivers](/database/drizzle/drivers) lists the package for every other driver.

drizzle-kit is optional: it is the CLI that generates migrations. When it is installed, `nuxt dev` and `nuxt prepare` write a config for it to `.nuxt/capsa/db/<name>/drizzle.config.ts`, and the database's `config.ts` accepts a `kit` hook ([Config file](/database/drizzle/config-file)).

## Options

::field-group
:::field{name="provider" type="'drizzle'" required}
Builds the database with Drizzle.
:::

:::field{name="dialect" type="string" required}
The database family, such as `postgresql`, `mysql` or `sqlite`.
:::

:::field{name="driver" type="string" required}
The Drizzle driver that talks to the database. It must be one of the dialect's drivers, listed in [Drivers](/database/drizzle/drivers).
:::

:::field{name="migrations" type="false | 'manual' | 'onStart'"}
Defaults to `false`, which leaves migrations to drizzle-kit. `'manual'` ships them with the server so you apply them yourself, and `'onStart'` applies them when the server starts ([Migrations](/database/drizzle/migrations)).
:::

:::field{name="dir" type="string"}
The folder of the database's files inside the `server/` directory of the project and of every layer ([Schema](/database/drizzle/schema#move-the-folder)). Defaults to `capsa/db/<name>`; an absolute path or an alias stops the build.
:::

:::field{name="dataDir" type="string"}
The folder of the local database used when no connection is set. It exists only on drivers that keep the database in a file or folder, such as `pglite`, and defaults to `.data/capsa/db` ([Connection](/database/drizzle/connection)).
:::
::

A driver from another dialect:

```ts twoslash [nuxt.config.ts]
// @errors: 2322
export default defineNuxtConfig({
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'mysql', driver: 'postgres-js' },
    },
  },
})
```

## Connection and Drizzle options

`capsa.db` has no `connection` key: each database reads its connection from an environment variable such as `NUXT_CAPSA_DB_DEFAULT_CONNECTION`, so no secret lands in `nuxt.config.ts` ([Connection](/database/drizzle/connection)). Options for `drizzle()` itself, such as `logger`, go in the database's `config.ts` ([Config file](/database/drizzle/config-file)).

## Another driver per environment

Nuxt's `$development` key gives `nuxt dev` a driver of its own. Repeat the whole database entry there, since Nuxt expects every key, and keep the dialect so both drivers share the same migrations.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'postgresql', driver: 'node-postgres', migrations: 'onStart' },
    },
  },
  $development: {
    capsa: {
      db: {
        default: { provider: 'drizzle', dialect: 'postgresql', driver: 'pglite', migrations: 'onStart' },
      },
    },
  },
})
```
