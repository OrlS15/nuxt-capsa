title: Schema

---

A database's tables are Drizzle tables in its own folder, `server/capsa/db/<name>/`. Every export of those files becomes part of the database.

```ts twoslash [server/capsa/db/default/schema/users.ts]
import { pgTable } from 'drizzle-orm/pg-core'

export const users = pgTable('users', t => ({
  id: t.serial().primaryKey(),
  name: t.text().notNull(),
  email: t.text().notNull().unique(),
  createdAt: t.timestamp().defaultNow().notNull(),
}))
```

Tables, column types, constraints and casing are written as in Drizzle: [Schema declaration](https://orm.drizzle.team/docs/sql-schema-declaration), [Column types](https://orm.drizzle.team/docs/column-types), [Camel and snake casing](https://orm.drizzle.team/docs/sql-schema-declaration#camel-and-snake-casing).

## Schema files

Capsa reads `schema.ts`, every `.ts` file in `schema/` and its subfolders, or both. Each database has its own folder, named after its key in `capsa.db`.

```bash [Project]
server/capsa/db/
├── default/
│   └── schema/
│       ├── comments.ts
│       ├── posts.ts
│       └── users.ts
└── analytics/
    └── schema.ts
```

Relations between the tables go in a `relations.ts` next to them ([Relations](/database/drizzle/relations)), and a Nuxt layer can add tables to the same database ([Layers](/database/drizzle/layers)).

## Move the folder

The `dir` option moves a database's folder to another path inside `server/`.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'postgresql', driver: 'pglite', dir: 'database/main' },
    },
  },
})
```

The tables then go in `server/database/main/schema.ts` or `server/database/main/schema/`.

## Imports between files

drizzle-kit loads the schema files on its own, outside Nuxt, so they import each other with relative paths.

```ts twoslash [server/capsa/db/default/schema/posts.ts]
// @filename: server/capsa/db/default/schema/users.ts
import { pgTable } from 'drizzle-orm/pg-core'

export const users = pgTable('users', t => ({
  id: t.serial().primaryKey(),
  name: t.text().notNull(),
  email: t.text().notNull().unique(),
  createdAt: t.timestamp().defaultNow().notNull(),
}))
// @filename: server/capsa/db/default/schema/posts.ts
// ---cut---
import { pgTable } from 'drizzle-orm/pg-core'
import { users } from './users'

export const posts = pgTable('posts', t => ({
  id: t.serial().primaryKey(),
  authorId: t.integer().notNull().references(() => users.id),
  title: t.text().notNull(),
  body: t.text(),
  publishedAt: t.timestamp(),
}))
```

::warning
An alias such as `~~/server/…` or `#capsa/db/default/schema` passes the type check, but `drizzle-kit generate` then stops with `Cannot find module '#capsa/db/default/schema'`.
::

## Tables in server code

`#capsa/db/<name>/schema` exports each table of a database.

```ts twoslash [server/api/users.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { users } from '#capsa/db/default/schema'

export default defineEventHandler(async () => {
  const rows = await useCapsaDb().select().from(users)
  //    ^?
  return rows
})
```

`#capsa/db/<name>` exports the same tables together, as the `schema` namespace.

```ts twoslash [server/api/events.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { schema } from '#capsa/db/analytics'

export default defineEventHandler(() => {
  return useCapsaDb('analytics').select().from(schema.events)
})
```

Each module holds only its own database's tables:

```ts twoslash [server/api/events.get.ts]
// @errors: 2305
import { events } from '#capsa/db/default/schema'
```

For queries, see [Queries](/database/drizzle/queries).

## Row types in `shared/`

Code in `shared/` also runs in the Vue app, where the `#capsa/db` modules don't exist, so it imports them with `import type`.

```ts twoslash [shared/types/post.ts]
import type { schema } from '#capsa/db/default'

export type Post = typeof schema.posts.$inferSelect
//          ^?
export type NewPost = typeof schema.posts.$inferInsert
```

Nuxt auto-imports the types of `shared/types/`, so the Vue app and server routes use `Post` without an import.

::warning
A value import from `#capsa/db` in `shared/` passes the type check too, but `nuxt build` fails with `Errored while resolving "#capsa/db/default"` once the Vue app runs that code.
::

## No schema files

A database without schema files still starts, with no tables, and Nuxt logs a warning:

```text [Terminal]
[capsa]  WARN  no schema files for db source "analytics" in /path/to/app/server/capsa/db/analytics.
```

## Changes during development

Adding or removing a schema file while `nuxt dev` runs updates the database's tables and reloads the server by itself. The database itself changes only through a migration: [Migrations](/database/drizzle/migrations).
