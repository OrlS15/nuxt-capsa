---
title: Relations
description: Declare how the tables of a database connect and load related rows with relational queries.
---

Relations tell Drizzle how the tables of a database point to each other, so one query can return a row with its related rows. Each database reads them from `relations.ts` in its folder, next to the schema.

```ts twoslash [server/capsa/db/default/relations.ts]
import { defineRelationsPart } from 'drizzle-orm'
import * as schema from '#capsa/db/default/schema'

export default defineRelationsPart(schema, r => ({
  users: {
    posts: r.many.posts(),
    comments: r.many.comments(),
  },
  posts: {
    author: r.one.users({ from: r.posts.authorId, to: r.users.id }),
    comments: r.many.comments(),
  },
  comments: {
    post: r.one.posts({ from: r.comments.postId, to: r.posts.id }),
    author: r.one.users({ from: r.comments.authorId, to: r.users.id }),
  },
}))
```

The tables come from `#capsa/db/<name>/schema`, which holds every table of that database. drizzle-kit never loads `relations.ts`, so the import works here, while [schema files](/database/drizzle/schema) need relative paths.

The file is optional: without it, `db.query.<table>` still reads every table but accepts no `with`. Drizzle documents `r.one`, `r.many` and their options: [Relations](https://orm.drizzle.team/docs/relations).

## Load related rows

`with` on `db.query.<table>` adds the relations you name to each row.

```ts twoslash [server/api/posts.get.ts]
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(async () => {
  const posts = await useCapsaDb().query.posts.findMany({
  //    ^?
    columns: { title: true },
    with: {
      author: { columns: { name: true } },
      comments: { columns: { content: true } },
    },
  })
  return posts
})
```

A relation left out of `with`:

```ts twoslash [server/api/authors.get.ts]
// @errors: 2551
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(async () => {
  const posts = await useCapsaDb().query.posts.findMany()
  return posts.map(post => post.author)
})
```

Filters, ordering, nested `with` and the rest of relational queries work as in Drizzle: [Relational queries](https://orm.drizzle.team/docs/rqb).

## Relations from layers

Capsa merges this file with the `relations.ts` of every [layer](/database/drizzle/layers#relations-in-a-layer), which is why it uses `defineRelationsPart` rather than Drizzle's `defineRelations`.
