Every key under `capsa.db` in `nuxt.config.ts` is a database that your server code can query. `provider` names the library that builds it, and you install that library's packages in your project.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-capsa'],
  capsa: {
    db: {
      default: { provider: 'drizzle', dialect: 'postgresql', driver: 'pglite', migrations: 'onStart' },
    },
  },
})
```

[Setup](/database/drizzle/setup) lists the packages and every option.

## Files

A database reads its files from `server/capsa/db/<name>/`: its tables in `schema.ts` or `schema/`, and optionally its relations, config and migrations.

```bash [Project]
server/capsa/db/default/
├── schema/
│   ├── users.ts
│   ├── posts.ts
│   └── comments.ts
├── relations.ts
├── config.ts
└── migrations/
```

[Schema](/database/drizzle/schema) shows how to write the tables, and [Config file](/database/drizzle/config-file) what `config.ts` changes.

## Queries

`useCapsaDb()` is auto-imported in server code and returns the `default` database. Its tables come from `#capsa/db/default/schema`.

```ts twoslash [server/api/users.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { users } from '#capsa/db/default/schema'

export default defineEventHandler(async () => {
  const rows = await useCapsaDb().select({ id: users.id, name: users.name }).from(users)
  //    ^?
  return rows
})
```

[Queries](/database/drizzle/queries) covers writes, explicit imports and reading the results in a page.

## Relations

`relations.ts` declares how the tables connect, and `with` loads the related rows in the same query.

```ts twoslash [server/api/posts.get.ts]
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(async () => {
  const posts = await useCapsaDb().query.posts.findMany({
  //    ^?
    columns: { title: true },
    with: { comments: { columns: { content: true } } },
  })
  return posts
})
```

[Relations](/database/drizzle/relations) shows the file.

## More databases

Any other key under `capsa.db` adds a database with its own folder, and `useCapsaDb()` takes its name.

```ts twoslash [server/api/events.get.ts]
import { defineEventHandler } from 'nuxt/server'
import { events } from '#capsa/db/analytics/schema'

export default defineEventHandler(() => {
  return useCapsaDb('analytics').select().from(events)
})
```

[Multiple databases](/database/multiple-databases) covers names, folders and variables.

## Connection

Each database reads its connection from an environment variable named after it, so no connection string goes in `nuxt.config.ts`. A driver that keeps the database in a local file or folder, such as `pglite`, uses one under `.data/capsa/db` while the variable is unset.

```bash [.env]
NUXT_CAPSA_DB_DEFAULT_CONNECTION=/srv/data/app
NUXT_CAPSA_DB_ANALYTICS_CONNECTION=/srv/data/analytics.db
```

[Connection](/database/drizzle/connection) covers the local default, read replicas and when connections open and close.

## Migrations

drizzle-kit writes migrations into the database's `migrations/` folder. With `migrations: 'onStart'` their SQL ships inside the server, which applies it as it starts.

```bash [Terminal]
npx drizzle-kit generate --config .nuxt/capsa/db/default/drizzle.config.ts
```

[Migrations](/database/drizzle/migrations) covers each mode and applying them from your code.

## Layers

A Nuxt layer adds tables to a database through schema files at the same folder path, and the project queries them like its own.

```bash [Project]
layers/shop/server/capsa/db/default/
└── schema/
    ├── orders.ts
    └── products.ts
```

[Layers](/database/drizzle/layers) covers relations across layers and the files that stay with the project.

## Drivers

`driver` picks how a database connects, among the drivers of its `dialect`. [Drivers](/database/drizzle/drivers) lists each one with its package and connection value.
