Every key under `capsa.drive` is a disk, a place where the server keeps files, such as a bucket on S3 or a folder on the machine. `adapter` names the [files-sdk](https://files-sdk.dev) adapter that stores the files, and server code uses the disk through `useCapsaDrive()`.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-capsa'],
  capsa: {
    drive: {
      default: { adapter: 's3-fetch' },
      avatars: { adapter: 's3-fetch' },
    },
  },
})
```

The `default` key is required, and any other name adds one more disk. Name a disk after what it holds rather than where it stores it, since the same disk can live in a folder during development and in a bucket in production.

## Install files-sdk

Capsa builds every disk with the files-sdk installed in your project, and needs version 3.1 or later.

::code-group
```bash [pnpm]
pnpm add files-sdk
```

```bash [npm]
npm install files-sdk
```

```bash [yarn]
yarn add files-sdk
```

```bash [bun]
bun add files-sdk
```
::

`adapter` takes the name files-sdk exports the adapter under, so `'s3-fetch'` is `files-sdk/s3-fetch`. Some adapters need packages of their own, and each one's [page in files-sdk's docs](https://files-sdk.dev/docs/adapters) lists them along with its options.

## Use a disk

`useCapsaDrive()` is auto-imported in server code and returns the `default` disk. Pass a name to get another one. What it returns is files-sdk's own `Files`, so [upload](https://files-sdk.dev/docs/api/upload), [download](https://files-sdk.dev/docs/api/download), [list](https://files-sdk.dev/docs/api/list), [url](https://files-sdk.dev/docs/api/url) and every other method work as files-sdk documents them.

```ts twoslash [server/api/avatars/[id].put.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(async (event) => {
  const file = (await event.req.formData()).get('file') as File
  const avatars = useCapsaDrive('avatars')
  //    ^?

  return avatars.upload(`users/${getRouterParam(event, 'id')}.png`, file)
})
```

Capsa adds one method, `serve`, which answers a request with a file ([Serve](/drive/serve)). A name that isn't configured:

```ts twoslash [server/api/avatars/[id].get.ts]
// @errors: 2345
const avatars = useCapsaDrive('avatar')
```

A disk is built the first time server code uses it, from the options its variables hold at that moment.

## Options from variables

A disk takes the options of its adapter from environment variables, one per option: `NUXT_CAPSA_DRIVE_`, then the disk's name and the option's name, both in upper snake case. For a disk on `s3-fetch`:

```bash [.env]
NUXT_CAPSA_DRIVE_DEFAULT_BUCKET=files
NUXT_CAPSA_DRIVE_DEFAULT_ENDPOINT=https://s3.eu-central-1.amazonaws.com
NUXT_CAPSA_DRIVE_DEFAULT_REGION=eu-central-1
NUXT_CAPSA_DRIVE_DEFAULT_ACCESS_KEY_ID=AKIA…
NUXT_CAPSA_DRIVE_DEFAULT_SECRET_ACCESS_KEY=…
```

| Disk | Option | Variable |
|---|---|---|
| `default` | `bucket` | `NUXT_CAPSA_DRIVE_DEFAULT_BUCKET` |
| `avatars` | `accessKeyId` | `NUXT_CAPSA_DRIVE_AVATARS_ACCESS_KEY_ID` |
| `userFiles` | `forcePathStyle` | `NUXT_CAPSA_DRIVE_USER_FILES_FORCE_PATH_STYLE` |

A variable holds text, and `true` or `false` becomes a boolean. An option that is an object or a function goes in the disk's [config file](/drive/config-file). When a required option is missing, the first request that uses the disk fails, and the error names the disk and where its options come from:

```text [Terminal]
[capsa] drive disk "default": s3-fetch adapter: missing endpoint. Pass `endpoint` (e.g. https://s3.us-east-1.amazonaws.com). Its options are its variables: NUXT_CAPSA_DRIVE_DEFAULT_<OPTION>.
```

The other disks keep working.

## Files on the machine

A disk on `fs` keeps its files in `.data/capsa/drive/<name>`, next to the local databases, until `NUXT_CAPSA_DRIVE_<NAME>_ROOT` names another folder. A common setup stores files in a bucket in production and in that folder during development, through Nuxt's [`$development`](https://nuxt.com/docs/4.x/getting-started/configuration#environment-overrides):

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  capsa: {
    drive: {
      default: { adapter: 's3-fetch' },
      avatars: { adapter: 's3-fetch' },
    },
  },
  $development: {
    capsa: { drive: { default: { adapter: 'fs' }, avatars: { adapter: 'fs' } } },
  },
})
```

files-sdk's `fs` adapter can't make links, so Capsa makes them for every disk on `fs`, and the code that hands out links runs unchanged on both ([Links](/drive/links#disks-on-fs)).

## Names

A disk's name may use the letters `a-z` and `A-Z`, digits and `_`, because it becomes part of its variables. Anything else stops the build, and so does an adapter written in another form than files-sdk's:

```text [Terminal]
ERROR  [capsa] invalid drive disk name "user-files": use only letters, numbers and "_".
ERROR  [capsa] drive disk "default" names "S3Fetch" as its adapter: write it as files-sdk exports it, like "s3-fetch" for files-sdk/s3-fetch.
```

When one disk's name starts with another's, each variable belongs to the disk with the longer name: `NUXT_CAPSA_DRIVE_USER_FILES_BUCKET` is the `bucket` of `userFiles`, never an option of a disk named `user`.
