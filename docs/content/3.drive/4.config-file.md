---
title: Config File
description: Give a disk the adapter options a variable can't hold, and the plugins of files-sdk.
---

A disk can have a `config.ts` in its folder, `server/capsa/drive/<name>/`. It holds what an environment variable can't: adapter options that are functions or objects, and the [plugins](https://files-sdk.dev/docs/plugins) of files-sdk.

```ts twoslash [server/capsa/drive/default/config.ts]
import { usage } from 'files-sdk/usage'
import { defineDriveConfig } from 'nuxt-capsa/drive'

export default defineDriveConfig('default', {
  options: () => ({
    fetch: (request) => {
      console.log(request.method, request.url)
      return fetch(request)
    },
  }),
  plugins: [usage()],
})
```

The file is optional, and only the project's file counts: a layer's `config.ts` for the same disk is ignored. `nuxt dev` restarts when the file is created or deleted, so the disk picks it up.

## Name the disk

The first argument of `defineDriveConfig` names the disk the file belongs to, as `defineDbConfig` names a database, so `options` is typed by that disk's adapter. A name that isn't configured:

```ts twoslash [server/capsa/drive/avatars/config.ts]
// @errors: 2345
import { defineDriveConfig } from 'nuxt-capsa/drive'

export default defineDriveConfig('avatar', {
  options: () => ({ forcePathStyle: true }),
})
```

## Options

`options` receives the options the disk's variables set, along with Capsa's own defaults such as the `root` of a disk on `fs`, and returns only what it changes. Capsa merges the result over them: your values win, nested objects merge, and `undefined` keeps the variable's value. It runs once, when the disk is built. Each adapter's options are on its [page in files-sdk's docs](https://files-sdk.dev/docs/adapters).

## Plugins

`plugins` takes files-sdk plugins, which run after Capsa's own. The methods they add become the disk's, typed, so a disk with the [usage](https://files-sdk.dev/docs/plugins/usage) plugin has `usage()`:

```ts twoslash [server/api/storage.get.ts]
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(() => {
  const stats = useCapsaDrive().usage()
  //    ^?
  return stats.operationsByKind
})
```

Every call made through the disk goes through its plugins, the ones `serve` makes among them. A link skips them, since the store answers it directly, and the route that answers the links of a disk on `fs` reads its files the same way.
