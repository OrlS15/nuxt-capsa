---
title: Links
description: Hand the browser a link to download a file or to upload one, on every disk including those on fs.
---

A browser never talks to a disk directly. A route of your app asks the disk for a link and returns it, and the browser downloads from that link or uploads to it. On a bucket, the file's bytes then go between the browser and the store without passing through your server.

## Download links

`url()` is files-sdk's own [url](https://files-sdk.dev/docs/api/url). With `expiresIn`, it returns a signed link that works for that many seconds, which suits files only some users may read:

```ts twoslash [server/api/invoices/[id].get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive().url(`invoices/${getRouterParam(event, 'id')}.pdf`, { expiresIn: 600 }))
```

Without options, a disk whose adapter has a `publicBaseUrl`, set by a variable such as `NUXT_CAPSA_DRIVE_AVATARS_PUBLIC_BASE_URL`, returns the file's permanent public link, which suits files anyone may read. Any other disk returns a signed link with its adapter's default expiry, one hour unless its `defaultUrlExpiresIn` says otherwise. Since `expiresIn` always asks for a link that expires, it is signed even on a disk with a `publicBaseUrl`:

```ts twoslash [server/api/avatars/[id].get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(async (event) => {
  const avatars = useCapsaDrive('avatars')
  const key = `users/${getRouterParam(event, 'id')}.png`

  return {
    image: await avatars.url(key),
    original: await avatars.url(key, { expiresIn: 60 }),
  }
})
```

A link returned as JSON expires on its own schedule, so it doesn't fit where an address has to keep working, such as an `<img src>` in cached HTML or a link in an email. [Serve](/drive/serve) answers a route of your app with the file instead.

## Upload links

`signedUploadUrl()` is files-sdk's [signedUploadUrl](https://files-sdk.dev/docs/api/signed-upload-url). Your route returns its result, and the browser sends the file to `url` with `method` and `headers` as files-sdk shows. With a `contentType`, the store accepts only a file of that type:

```ts twoslash [server/api/avatars/[id]/upload.post.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive('avatars').signedUploadUrl(`users/${getRouterParam(event, 'id')}.png`, { expiresIn: 60, contentType: 'image/png' }))
```

For a file that should pass through your server, for example to check it first, the route reads the form and calls `upload()` itself, as on the [Overview](/drive/overview#use-a-disk).

## Disks on fs

files-sdk's `fs` adapter has no way to make links, so Capsa makes them for every disk on `fs`. `url()` and `signedUploadUrl()` work as they do on S3, and return a signed link to a route Capsa adds to your app, which checks the signature and answers with the file or stores the upload.

```text
/_capsa/drive/default/invoices/42.pdf?expires=1793452800&signature=9f86d081…
```

The link has no origin and starts at `app.baseURL`, so a page of the app uses it as it is, while an email needs the site's origin in front of it. It works only for the method it was signed for, `GET` to download and `PUT` to upload, and only until it expires: one hour without `expiresIn`, as on files-sdk. An upload link signed with a `contentType` takes only a request with that `Content-Type`, as S3 does. An expired link, or one whose key, expiry or signature was changed, gets a `403`.

Capsa signs the links with a key derived from `NUXT_APP_SECRET`. `nuxt dev` generates a secret when none is set, but a built server signs no links until the variable holds one of at least 32 characters, such as the output of this command. A new secret ends every link signed with the old one.

```bash [Terminal]
openssl rand -base64 32
```
