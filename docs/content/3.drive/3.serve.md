---
title: Serve
description: Answer a route of your app with a file, by redirecting to a link of the store or by streaming its bytes.
---

Capsa adds `serve` to every disk. It answers a request with a file, so a route of your app becomes the file's stable address, one that an `<img src>`, cached HTML or an email can keep using after any link of the store has expired.

```ts twoslash [server/api/avatars/[id].get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive('avatars').serve(event, `users/${getRouterParam(event, 'id')}.png`))
```

The route decides who may read the file, as for any other route, and `serve` answers in one of two modes.

## Redirect

By default, `serve` answers with a `302` to a link it makes on the spot with the disk's `url()`, and the browser downloads the file from the store. `expiresIn` is that link's: without it, the link is public on a disk with a `publicBaseUrl` and signed for an hour on any other, as [Links](/drive/links#download-links) explains. On a disk on `fs`, the redirect goes to the link Capsa signs for it.

```ts twoslash [server/api/invoices/[id].get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive().serve(event, `invoices/${getRouterParam(event, 'id')}.pdf`, { expiresIn: 60 }))
```

A redirect needs a disk that can give a link: where its `url()` throws, the redirect throws the same error, and proxy mode serves the file instead.

## Proxy

With `mode: 'proxy'`, the bytes come through your server. `serve` streams them from the store as they arrive and never holds the whole file in memory, with the file's `Content-Type` and `Content-Length`. A file that doesn't exist gets a `404`.

```ts twoslash [server/api/videos/[id].get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive().serve(event, `videos/${getRouterParam(event, 'id')}.mp4`, { mode: 'proxy' }))
```

A proxied file answers a `Range` request with only the bytes it asks for, as a `206`, which lets a video player seek. A range past the end of the file gets a `416`. A request for several ranges at once gets the whole file as a `200`, and so does a range the store itself ignores, since some stores send the whole file whatever was asked.

No link is made in proxy mode, so it takes no `expiresIn`:

```ts twoslash [server/api/videos/[id].get.ts]
// @errors: 2353
import { defineEventHandler } from 'nuxt/server'

export default defineEventHandler(event =>
  useCapsaDrive().serve(event, 'videos/intro.mp4', { mode: 'proxy', expiresIn: 60 }))
```

## Download

`download` names the file the browser saves, instead of showing it in the page. It works in both modes: in a redirect it becomes part of the signed link, and in proxy mode it is the response's `Content-Disposition`.

```ts twoslash [server/api/invoices/[id]/download.get.ts]
import { defineEventHandler, getRouterParam } from 'nuxt/server'

export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')

  return useCapsaDrive().serve(event, `invoices/${id}.pdf`, { download: `invoice-${id}.pdf` })
})
```

::warning
Files your users upload can be HTML or SVG, whose scripts a browser runs when it shows them. In proxy mode, and through the links of a disk on `fs`, a file comes from your app's own origin, where those scripts would run as if they were your app's. Serve your users' files with `download`. Capsa also sends `X-Content-Type-Options: nosniff` with every file it streams, which tells the browser to keep to the type the file was stored with.
::
